# Асинхронный микросервис аудита безопасности Docker-образов

## Назначение и возможности
Сервис принимает запросы на проверку Docker-образов, ставит задачу в очередь и асинхронно сканирует образ на уязвимости с помощью Trivy, сохраняя историю и отчеты в PostgreSQL и отправляя отчет о результате.

## Сценарий работы
1. Клиент отправляет `POST /scans` с именем образа на публичный IP VM-1 (`api`).
2. API создает запись со статусом `queued` в PostgreSQL и кладет задачу в очередь Redis.
3. Воркер на VM-2 забирает задачу из Redis, запускает `trivy image --format json` внутри контейнера, обновляет статус на `running`, затем на `completed` (или `failed`) и сохраняет сводку и отчет в PostgreSQL.
4. Отправляется отчет по webhook (если задан `REPORT_WEBHOOK_URL`), а полный результат доступен по `GET /scans/{id}`.

## Компоненты облачной инфраструктуры
- **VM-1 (Ubuntu, публичный IP):** API-сервер в Docker-контейнере.
- **VM-2 (Ubuntu, приватный IP):** воркер с Trivy в Docker-контейнере.
- **Приватная сеть:** связывает VM-1, VM-2 и управляемые/облачные сервисы БД и очереди.
- **Облачная PostgreSQL:** хранение истории задач, статусов и результатов сканирования.
- **Redis:** брокер очереди задач между API и воркером.

## Архитектура и взаимодействие компонентов
`Client (Internet) -> [Public IP:8000] VM-1 (API) -> Redis Queue -> VM-2 (Private IP, Trivy Worker) -> PostgreSQL`

## Адрес сервиса
- Базовый URL по публичному IP: `http://<ПУБЛИЧНЫЙ_IP_VM1>:8000`
- Проверка здоровья: `GET http://<ПУБЛИЧНЫЙ_IP_VM1>:8000/health`
